# Membership Disclosure without Sequence Reproduction

**English** | [简体中文](README.zh-CN.md)

Code and measurements for *Membership Disclosure without Sequence Reproduction:
Privacy Leakage from Fine-Tuned Genomic Language Models*.

We study candidate-record membership ranking and exact sequence recovery in
fine-tuned genomic language models, comparing contextual access, scoring, decoding,
and tokenization across eight released checkpoints and a controlled transformer.

## Main findings

| Experiment | Reported result | Scope |
| --- | --- | --- |
| DNABERT-2, chr22, single-copy records | Fresh-window rank-1: **18–26%**; matched controls: **0%** | Final checkpoint, three training seeds, 50 records per seed, 100 alternatives |
| Controlled synthetic canaries | 2-mer / 6-mer exact recovery: **0% / 92%** | Sixteen insertions, matched held-out loss **2.40 bits/nt** |

In the reported DNABERT-2 single-copy evaluations, neither tested decoder recovers
the hidden 48-nt target; their checkpoint coverage differs. This is not a universal
zero: separate NT experiments recover single-copy targets at 8% (250M) and 12–18%
(500M). Candidate ranking is **not personal identification or calibrated low-FPR
membership inference**. Training seeds reuse the same records. Matched background
loss does not establish equal target predictability or slot count as the sole mechanism.

## Quick start: regenerate figures and tables

Run from a fresh clone. This path needs no GPU, model weights or genomic downloads.

```bash
git clone https://github.com/yi-qian-zhang/membership-disclosure-without-reproduction.git
cd membership-disclosure-without-reproduction
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements-analysis.txt
python -m pilot2.figures_main10 --out reproduced/figures
python -m pilot2.appendix_tables --results results --out reproduced/tables
python -m pilot2.appendix_source_cells --summary results/appendix_source_cells.json --tables-out reproduced/tables
python -m pilot2.compact_appendix --tables reproduced/tables --out reproduced/tables
```

**Fonts:** the plotting command requires Arial. Install it, or set
`GLMEXT_FONT_DIR` to a local directory containing the regular, bold, italic and
bold-italic TTF files. Fonts are not bundled. Table generation does not require Arial.

The commands regenerate **Figures 2–3 and 22 TeX table fragments** (13 source tables plus nine compact fragments) from committed
measurements, writing to ignored `reproduced/`. Figure 1 is a separate editable
PowerPoint figure; its [source and export instructions](paper/figures/F1_source.md)
are included. This repository's `paper/` contains figure assets, not a complete
LaTeX manuscript.

## Figure and table provenance

`figures_main10` regenerates the two main quantitative figures (F2/F3). Figure 1 is
an editable PowerPoint illustration exported through Microsoft PowerPoint; it is not
generated by the plotting command. Its endpoint surprise values come from
`results/kcurve_per_nt.json`. `results/figure_data.csv` supplies the main plotted
trajectories; additional JSON/Markdown measurements supply the generated tables.
See [results/README.md](results/README.md) for provenance and release boundaries.

The `appendix_source_cells` command regenerates the supplementary HyenaDNA epoch-30 and overlapping
DNABERT full-50-record tables from an aggregate source manifest. With access to
the original `outputs/`, run `python -m pilot2.appendix_source_cells --root .`
to independently recount the saved evaluations and print their source hashes.
The manifest also records the candidate-scorer audit with member/control counts;
it contains no sequences or individual record identifiers.

The six-task utility table uses the unrounded aggregates and source coverage in
`results/dnabert_gue_ds/utility_downstream.json`. Repeated task panels from the same
training configuration, seed and checkpoint are merged before averaging. Tasks use
their available seeds; this is not a balanced panel across every task and epoch.
The appendix-table command above regenerates this table without private outputs.
To rebuild its aggregate manifest from the original saved evaluations:

```bash
python -m pilot2.analyze_downstream \
  --root outputs/dnabert_gue_ds outputs/dnabert_gue_ds2 outputs/dnabert_yeast_ds \
         outputs/hyena_gue_ds outputs/hyena_gue_ds2 outputs/hyena_yeast_ds \
  --out-dir reproduced/utility
```

To rebuild the additional quantitative appendix plots from published aggregates:

```bash
python -m pilot2.figures_privacy --out reproduced/figures
```

The compact-table formatter copies numeric cells, adjusts presentation labels, and
removes code filenames from table notes. It does not recompute estimates or change
weighting. Its two cross-family tables can fall back to the verified archive if their
canonical generated fragments are absent.

## Reproduce model measurements

The recorded training environment used Python 3.10.18, PyTorch 2.1.1 with CUDA 12.1,
transformers 4.29.2 and tokenizers 0.13.3. `requirements-paper.txt` records the core
analysis/model dependencies; individual model backends may require their additional
packages. The collaboration checkout's `requirements/requirements.txt` is a broader
environment snapshot, not a minimal installation recipe. Full GPU training is separate
from the lightweight figure/table checks above.

```bash
python -m pip install -r requirements-paper.txt
export GLMEXT_DATA=/path/to/genomic-inputs
```

Place the IGSR GRCh38 recall file `ALL.chr22.GRCh38.phased.vcf.gz` and the matching
chromosome-22 reference FASTA `chr22.fa` under `$GLMEXT_DATA/human/`. The VCF contains
2,548 samples; this count belongs to the GRCh38 recall, not the 2015 phase-3 publication.
The phased call set was announced on 12 March 2019. Its chromosome-22 VCF is dated
27 February 2019 and names `GRCh38_full_analysis_set_plus_decoy_hla.fa` as its
reference: the GRCh38 assembly with decoy and HLA sequences. These are upstream
data filenames, not scripts. `chr22.fa` is the local chromosome-specific input
expected by the builder. Exact filenames and file dates are documented here;
the paper supplement retains the scientific dataset and reference-assembly names.
The main experiment uses the builder's historical positional construction:

```bash
python -m pilot2.human_canary
python -m pilot2.canary_census
```

Do not add `--phased` when reproducing the reported record set. The historical builder
does not guarantee a phased haplotype: of 400 windows, the audit identifies 145 observed
haplotypes, 20 within-person genotype composites and 235 unobserved composites. The
rare-carrier criterion applies to the anchor variant, not automatically to the window.

For example, one NT 250M fine-tuning run is:

```bash
python -m pilot2.nt --size 250m --data human --epochs 50 --mask_rate 0.15 \
  --canary_npz "$GLMEXT_DATA/human/canaries_chr22.npz" \
  --probes_per_tier 50 --pool 100 --seed 0 --out outputs/nt_human_s0
python -m pilot2.recon_audit --root outputs/nt_human_s0 --ckpt ckpt_ep50.pt --restarts 128
```

Use each reported run's `args.json`, the dated `pilot2/queue_*.sh` invocations and the
paper's configuration/measurement appendices for the other arms. A generic example
does not reproduce every table cell. The NT example writes `ckpt_ep<N>.pt`; checkpoint naming differs across backends,
so use the filenames recorded for the run being reproduced.

## Decoder commands and budgets

| Protocol | Vocabulary / role | Reported budget or qualification |
| --- | --- | --- |
| Prefix decoding | Sequential generation in the model's vocabulary | One greedy left-to-right generation pass; no beam, sampling or restarts |
| `pilot2/recon_audit.py` | Non-overlapping tokens, re-masking ICM | NT remeasurement: 128 restarts, up to six sweeps |
| `pilot2/recon_overlap.py` | Overlapping k-mers, nucleotide updates | Main remeasurement: 16 restarts, four sweeps |
| `pilot2/recon_bpe.py` | BPE, nucleotide proposals with re-tokenization | Main historical campaign: 16 restarts, four sweeps; common-interval correction audited separately |

Run from the repository root after setting `GLMEXT_DATA` to your public-data root.
Noninteractive shells do not necessarily source `.bashrc`; export the variable in
the shell that launches the job. Paths below require reconstructed local runs.
Use new output names or an isolated copy to avoid overwriting historical artifacts.

```bash
export GLMEXT_DATA=/path/to/glm_data
NT=outputs/nt_ckpt/nt250m_mlm_human_s0
DB5=outputs/dnabert_long/dnabert5_nt0.05_lr0.0001_human_s0
BPE=outputs/bpe_human/dnabert2bpe_human_s0

python -m pilot2.recon_audit --root "$NT" --ckpt ckpt_ep50.pt \
    --restarts 128 --max_probes 50 --name reproduction_rb_ep50
python -m pilot2.recon_overlap --root "$DB5" --ckpt ep120.pt \
    --restarts 16 --max_probes 50 --name reproduction_rb_ep120
python -m pilot2.recon_bpe --root "$BPE" --ckpt ep120.pt \
    --restarts 16 --max_probes 50 --score pernt --name reproduction_rb_ep120
```

The last command reproduces the **historical divided BPE scorer**, not the
common-interval correction. Use `--score fixed` for that separate audit and a
different output name. Its paper coverage is only 60 seed-0 final cells, not the
whole three-seed trajectory. Earlier reconstruction runs used 32 restarts; the
reported chromosome-22 nucleotide searches use 16, while token re-masking uses 128.
`--chunk 1` on the token re-masking path reproduces the historical single-row
arithmetic; larger bf16 batches can change near-tied argmaxes. This is not a claim
that every platform is bitwise reproducible.

Prefix decoding is greedy over admissible tokens: one left-to-right generation
pass, one model evaluation per generated slot, with no beam or restart. It feeds
back predictions. The 48-nt endpoint does not imply that its token-boundary input
reveals exactly 48 nt or that whole boundary tokens are evaluated for exactness.

## Controlled tokenizer sweep

```bash
EXTRA="--epochs 30 --tiers 1,4,16 --probe_offset random"
EXTRA="$EXTRA --probes_per_tier 100 --n_nonmember 100"
EXTRA="$EXTRA --save_epochs 1,2,3,5,8,12,20,30 --score_snapshots"
PILOT2_WINDOW=300 bash pilot2/sweep.sh outputs/kcurve300 "ar" "0 1 2" \
    "$EXTRA" "char 2mer 3mer 4mer 5mer 6mer"
python -m pilot2.kcurve_report --root outputs/kcurve300

python -m pilot2.rescore --root outputs/bpe_human/dnabert2bpe_human_s0 \
    --ckpt ep120.pt --name reproduction_ep120 --compare scores_ep120.json

# Requires original reconstructed run artifacts; do not replace published CSVs blindly.
python -m pilot2.export_figure_data --root outputs --out reproduced/figure_data.csv```

`sweep.sh` activates the recorded `glm` environment; adapt that environment setup
for another installation. Training and checkpoint rescoring require reconstructed
inputs and weights and are separate from the aggregate-only quick start. The CSV
export above goes to `reproduced/`; plotting commands otherwise read the committed
`results/`, so a new export does not silently replace the paper's measurements.

## Release boundaries and interpretation

All source inputs are public. The release includes aggregate measurements and
redacted evaluation records, but not the consolidated human canary collection,
anchor-to-sample links, or fine-tuned weights. Reconstructing inputs and retraining
are separate from replaying published tables. Three training seeds reuse records
and do not constitute independent cohort replications. One numerical replay changed
extraction by six percentage points; that is not a general variance estimate or a
guarantee that membership rankings will be stable across platforms.

Legacy JSON fields such as `bound` and `loo_bound` keep their names and numeric
values for compatibility. They are conditional-prediction power summaries, not
certified recovery bounds. Search scores cropped 48-nt recovery while token LOO may
score complete covering tokens, and batched versus single-row numerical paths can
differ. Aligned counterexamples also exist. Early stopping does not rescue the
recordwise claim; zero exact recovery in BPE does not validate it either. The
abstract complete-state implication in the historical supplement requires identical
update maps, constraints, arithmetic and tie-breaking and does not certify the
reported outputs.

In a separate synthetic-canary experiment with sixteen copies, 2-mer and 6-mer
tokenizers recover 0% and 92% at matched held-out loss 2.40 bits/nt. This comparison
holds the backbone, objective and corpus fixed. It does not establish equal target
predictability or slot count as the sole explanation. At the end of training,
planted covering-token surprise is 0.824 versus 0.0052 bits per target nucleotide.
It scores complete covering tokens (including trailing host letters), normalized
by 48 target nucleotides, rather than marginalizing a strict 48-nt event. These are
different checkpoints from the matched-loss comparison.

The overlapping DNABERT family uses two separate campaigns: the 50-epoch causal
fine-tuning arm supplies the cross-family membership comparison; the 150-epoch masked
arm supplies the stronger-decoder and leave-one-out diagnostics. They do not share
checkpoints. Both the manuscript and its configuration table distinguish these arms.

### Measurement campaigns and conditional diagnostics

The common-basis decoder remeasurement comprised 19 chromosome-22 run/checkpoint
pairs on 23 October and seven E. coli pairs on 19 October. Earlier objective,
placement, edge-conditioned, downstream and capacity controls were not all rerun
after the 18 October host reboot. A paired replay changed extraction by six
percentage points while reproducing rank-1 and held-out loss to reported precision;
this is not a numerical-variance estimate.

For the final single-copy DNABERT-2 seed-0 diagnostic, mean LOO accuracy is 0.945
and mean per-record power is 0.268, whereas raising mean accuracy to the 48th power
gives 0.065. These are different aggregations, not recovery probabilities. The
checkpoint/seed/crop and true-context qualifications in the diagnostic section apply.

For completeness, the human single-copy subset counts retained in the main text
are 5/21, 5/21, 8/21 fresh-window hits among compatible records and 1/23, 3/23, 0/23
among unobserved composites. Grouping by allele count instead gives 27/78 versus
6/72 scorings: 26 single-variant and 24 multi-variant records, each reused across
three training seeds. These denominators are not independent participant samples.

### Separate fine-tuned-head comparison

This evaluation is distinct from the frozen probes in the utility table. It uses
two rounds over at most 20,000 labeled sequences; the published recipe uses three
to five rounds, depending on task, over the full split. All available MCC values,
including zeros, enter 252 model/round/task summaries from 476 evaluations.
DNABERT-2's fine-tuned head improves on four of six tasks over the evaluated
best-held-out-to-final interval. Its best score per task remains below the matching
published DNABERT-2 score by:

| Task | MCC gap |
| --- | ---: |
| H3 | 0.039 |
| Promoter | 0.049 |
| TF dataset 0 | 0.057 |
| H3K4me3 | 0.069 |
| Core promoter | 0.085 |
| Splice | 0.095 |

The comparator is the plain DNABERT-2 row for the same datasets, as documented in
the [archived downstream section](docs/appendix_reference_20261103/sections/p11_appendix.tex)
and `results/dnabert_gue_ds/utility_downstream.json`. TF uses dataset 0, not the
five-dataset average. These reduced-recipe comparisons do not establish benchmark parity.

### Redrawing the member/control split

Here **excess** means **non-member surprise minus member surprise**, in bits per
nucleotide, at the same checkpoint. This is the statistic implemented in
`pilot2/analyze_matched.py`; it is not a participant-identification rate or proof
that all of the score difference was caused by training membership.

Four split redraws show that the initial pretrained offset is not a fixed quantity
to subtract. Round-1 excess was reported as 0.00 +/- 0.05 across the tested draws;
regression slopes of round-50 excess on the initial offset were 0.05--0.19.
Three draws permit matched-loss comparisons; the fourth has nonoverlapping loss
branches. Across the comparable draws, single-copy excess varies by 0.06--0.27
bits/nt and sixteen-copy excess by 0.07--0.64. Full rows remain in the
[split table](docs/appendix_reference_20261103/tables/t_draws.tex) and reports under
`results/human_ds2345/`, `results/human_ds3456/` and `results/human_ds4567/`.
The observed sensitivity motivates within-condition controls; it does not establish
stability under new participant samples.

For the corpus-size sweep, matching held-out loss compares a common predictive-loss
level. It **does not independently control optimization updates**: update count remains
confounded with corpus size, and participant composition is not manipulated.
